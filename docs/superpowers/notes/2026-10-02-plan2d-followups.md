## UI / UX
- Transfers can't be the last toolbar item while it lives in ContentView, because SwiftUI renders the parent's toolbar items before the browser's. It stays in its own capsule left of the view picker. Moving it into BrowserView would hide it on the no-phone and device-state screens.
- If the helper wedges at launch, the no-phone guide shows after 10 s even with a phone plugged in. There is no retry for a `devices()` call that never returns.
- The transfer VoiceOver text doesn't say whether a transfer is a download or an upload.
- «Загрузить N объектов» (Download N Items) doesn't say which direction; «Загрузить на Mac: N …» would be clearer.
- «новая папка» could become Finder's «папка без названия». This is a style choice.

## Code / tests
- `scripts/sync-strings.sh` (via xcstringstool) strips the catalogs' trailing newline. This is cosmetic churn.
- The `testRussianUI` check `buttons["Transfers"]` is vacuous because the button is identified as `transfersButton`. Assert that its label is «Передачи» instead.
- `MTPError.libmtpCode(0)` gives -100, outside the documented range starting at -101. It's harmless.
- The AppModel launch timer swallows cancellation, so `markLoaded` still runs after the timer is cancelled. Harmless today.
- `FlakyService.hangDevices` is unused scaffolding.
- The subtitle's folder-error guard is untested.
- The scheme's test action runs only the UI tests, which take over the screen. Consider a separate UI-test scheme when unit tests join the Xcode scheme.
- The English entries for positional-argument keys sit in state "new". They're generated by xcstringstool and harmless.
